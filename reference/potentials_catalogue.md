# Interatomic-potential catalogue for nanometric cutting / nano-scratching MD in LAMMPS

Scope: diamond (C) tool, rigid or deformable; workpieces 3C/4H/6H-SiC, Si, Ge, Si-Ge, Cu, Al, Ni, Fe, Ti, Au, Ag, W, GaAs, GaN, diamond, (a-SiO2 optional).

Sources used:
- **[M]** = LAMMPS manual, release **30Sep2026** (local `manual.txt`, section numbers quoted, e.g. M 4.299 = `pair_style tersoff`).
- **[F]** = header lines of the potential files bundled in `.../lammps/share/lammps/potentials/` of the installed `lammps` Python wheel (`lmpenv`). Element tokens below are copied **verbatim** from the files; they are what `pair_coeff` must use.
- **[W]** = web-verified literature values (URLs given). Anything not confirmed is marked **UNVERIFIED**.

All bundled files listed here carry `UNITS: metal` (eV, Angstrom, ps, g/mol) -> use `units metal`. LAMMPS reads the `UNITS:` tag and aborts on mismatch (M 1.75). Tersoff/SW/EAM-type files can be auto-converted metal<->real (warning printed) but **not** to other unit styles.

## 1. Syntax rules that every script below relies on (manual, verbatim meaning)

### 1.1 `pair_coeff` element -> type mapping (M 1.75, 4.100, 4.299, 4.294, 4.311, 4.195)
- Many-body file-based styles (`tersoff`, `tersoff/mod`, `tersoff/zbl`, `sw`, `vashishta`, `edip`, `gw`, `meam`, `meam/spline`, `eam/alloy`, `eam/fs`, `airebo`, `rebo`, `lcbop`, `bop`, `extep`, `snap`, `mliap`) take **exactly one** `pair_coeff` whose first two args **must be `* *`**, followed by the file name and then **N element names, one per LAMMPS atom type, in type order** (N = number of atom types).
  `pair_coeff * * SiC.tersoff Si Si Si C` -> types 1,2,3 = Si, type 4 = C.
- `NULL` in a mapping slot = "this atom type is not handled by this sub-style"; used only under `pair_style hybrid*`. Example from M 4.144: `pair_coeff * * eam/alloy nialhjea Ni Ni NULL`.
- `pair_style eam` (funcfl `.eam` files) is the exception: it is assigned **per I,I pair**, e.g. `pair_coeff 1 1 Cu_u3.eam`; cross pairs I!=J are generated by DYNAMO-style mixing from the two funcfl files (M 4.100). With `eam/alloy` / `eam/fs` (setfl) there is no mixing; the file contains all cross terms.
- `meam`: `pair_coeff * * library.meam El1 El2 param.meam El1 El2 ...` -- library file, the list of elements to extract, parameter file (or `NULL`), then the N type mappings. **The element order between the two filenames fixes the numeric indices used inside the parameter file**, so it must match the parameter file (M 4.195). Cutoffs come from the files (`rc`), not from `pair_style`.
- `meam/spline` old-style single-element files (Ti.meam.spline, Si_1/2.meam.spline): only **one** atom type may be mapped to the element; all other slots must be `NULL` (M 4.196). Multi-type-per-element is unsupported.
- Cutoffs for Tersoff/SW/Vashishta/EAM/MEAM/BOP are **in the files** (R+D, a*sigma, rc, setfl cutoff). Cutoffs are given on the `pair_style` line only for pairwise styles (`morse`, `lj/cut`, `zbl inner outer`) (M 4.209, 4.162, 4.316).
- Potential files are searched in: given path, then `$LAMMPS_POTENTIALS` directories (Windows separator `;`) (M 1.75).

### 1.2 `pair_style hybrid` vs `hybrid/overlay` (M 4.144)
- `hybrid`: **exactly one** sub-style per type pair I,J. `hybrid/overlay`: one or more sub-styles per pair, contributions added.
- Every type pair I<=J must be assigned to at least one sub-style and **every sub-style must appear in at least one `pair_coeff`**, or LAMMPS errors.
- Many-body sub-styles still use the `* *` form with `NULL` placeholders; pairwise sub-styles use numeric `I J`.
- Sub-style name goes right after `I J`; if the same style is listed twice, an instance number follows the name: `pair_coeff * * tersoff 1 Si.tersoff Si NULL` / `pair_coeff * * tersoff 2 C.tersoff NULL C` (manual example).
- **No mixing across sub-styles, ever**; under `hybrid/overlay` mixing happens only for pairs that have a single sub-style. Give all cross terms explicitly. `pair_coeff I J none` removes a pair (allowed only for hybrid*).
- Manual's explicit warning (M 4.144, "When NOT to use a hybrid pair style"): combining many-body sub-styles via hybrid is only acceptable when they act on **different objects** ("a metal and a nano-machining workpiece" is the manual's own example) and the cross term is a **pairwise additive** potential (LJ or Morse). Combining EAM+EAM or Tersoff+Tersoff on the *same* atoms gives large embedding/bond-order errors.
- `pair_modify pair tersoff special lj/coul 1.0 1.0 1.0` is needed only if a molecular data file with bonds is used -- not for cutting setups.

### 1.3 Pairwise cross-term styles (M 4.209, 4.162, 4.316)
- `pair_style morse rc` ; `pair_coeff I J D0 alpha r0 [rc]` with E = D0[e^(-2a(r-r0)) - 2e^(-a(r-r0))], D0 in eV, alpha in 1/A, r0 in A. **Morse does not support mixing** -> every I,J needed must be given explicitly. `morse/smooth/linear` (EXTRA-PAIR package) shifts E and F to zero at rc -- recommended for cutting to avoid force discontinuity at rc.
- `pair_style lj/cut rc` ; `pair_coeff I J eps sigma [rc]`; mixes geometrically by default (`pair_modify mix arithmetic` available) -- but not across hybrid sub-styles.
- `pair_style zbl inner outer` ; `pair_coeff I J Zi Zj` (atomic numbers); purely repulsive, universal; usable as a safe repulsive tool/workpiece wall when no fitted cross term exists. Under hybrid it does not mix, so give every pair.
- `fix setforce 0 0 0` on the tool group (manual example: `fix freeze indenter setforce 0.0 0.0 0.0`) or `fix rigid tool single` / `fix rigid/nve` makes the tool rigid; combine with `velocity tool set ...` for a prescribed cutting speed. A rigid tool does **not** need any C-C potential, but every C-X type pair still has to be assigned to a sub-style (use `none`, `zbl`, or the cross Morse for C-C if you want to skip C-C; a `tersoff` mapping for C only is also fine and cheap if `neigh_modify exclude group tool tool` is set).

### 1.4 Tersoff file conventions (M 4.299)
- Entry = `El1 El2 El3  m gamma lambda3 c d costheta0 n beta lambda2 B R D lambda1 A`. El1 = centre atom, El2 = bonded neighbour, El3 = third atom modifying the 1-2 bond. Two-body parameters for pair i-j come from entry `i j j`; entries with El2!=El3 only need the 3-body part (2-body columns may be 0).
- A 2-element file needs all **8** triplets; 3 elements need 27. Missing triplets -> error (that is why SiCGe.tersoff cannot do Ge-C).
- `m=3, gamma=1` = original Tersoff form; `m=1, beta=1` = Albe/Erhart (ABOP) form. `tersoff/table` supports only the Tersoff_2 (m=3, lambda3=0) form.
- Original Tersoff `R',S'` -> LAMMPS `R=(R'+S')/2`, `D=(S'-R')/2`. Cutoff = R+D.

### 3.2 LJ / ZBL fallbacks
- LJ via Lorentz-Berthelot from single-element LJ parameters is common but ad hoc; LAMMPS will not mix across hybrid sub-styles, so write `pair_coeff I J lj/cut eps sigma rc` explicitly. Example in literature: C-Fe purely repulsive LJ (arXiv 1702.00457). No standard eps/sigma table was verified here - **UNVERIFIED**.
- `zbl 1.0 2.0`-type repulsive wall with `pair_coeff 1 2 zbl Z_work 6` is parameter-free and always safe for a rigid indenter/tool when only repulsion matters (no adhesion, no chip adhesion to tool).

### 3.3 Rigid vs deformable tool
- **Rigid** (most Cu/Si/Ge cutting papers): tool atoms in a group with `fix setforce 0 0 0` (or `fix rigid tool single`), `velocity tool set -vx 0 0`, `neigh_modify exclude group tool tool`. No C-C potential is *physically* needed, but the hybrid rules still require the C-C type pair to be assigned: either map C in a cheap sub-style (`tersoff` with `NULL` elsewhere) or `pair_coeff 2 2 none` (hybrid only).
- **Deformable** (tool wear, graphitisation studies): C-C via `tersoff` (SiC*.tersoff C entry, or SiCGe.tersoff `C`), `rebo`/`airebo` (CH.rebo/CH.airebo), or `lcbop`. Tersoff-89 C is cheapest and standard (Goel et al.).

## 4. Ready-to-use pair_style / pair_coeff blocks (types: 1 = workpiece element(s), last type = tool C unless noted)

All blocks assume `units metal`, `atom_style atomic`, `newton on` (required by Tersoff-family styles, M 4.299.5), and file names resolvable via `LAMMPS_POTENTIALS`.

### 4.1 3C/4H/6H-SiC workpiece + diamond tool, single Tersoff file (deformable tool, fully consistent)
Types: 1 = Si (workpiece), 2 = C (workpiece), 3 = C (tool).
```
pair_style  tersoff
pair_coeff  * * SiC_Erhart-Albe.tersoff Si C C      # or SiC_1994.tersoff / SiC_1989.tersoff / SiC.tersoff
```
Variant with ZBL core for violent contact: `pair_style tersoff/zbl` + `pair_coeff * * SiC.tersoff.zbl Si C C`.
Rigid tool: same lines + `fix 1 tool setforce 0 0 0` ; `neigh_modify exclude group tool tool` (saves time).
Vashishta alternative for the *workpiece only* (it has no C-C bonding, so the tool must be rigid or use hybrid):
```
pair_style  hybrid vashishta morse 6.5
pair_coeff  * * vashishta SiC.vashishta Si C NULL
pair_coeff  1 3 morse 0.435 4.6487 1.9475            # Si-C(tool), Section 3.1
pair_coeff  2 3 morse <D> <alpha> <r0>               # C(work)-C(tool): no verified set -> UNVERIFIED; use zbl or Tersoff instead
pair_coeff  3 3 none                                 # rigid tool
```

### 4.2 Si workpiece + diamond tool
(a) All-Tersoff, deformable or rigid tool (types 1 = Si, 2 = C):
```
pair_style  tersoff
pair_coeff  * * SiC_Erhart-Albe.tersoff Si C          # or SiC.tersoff / SiC_1994.tersoff, or SiCGe.tersoff Si(D) C
```
(b) SW silicon + Morse Si-C + rigid tool (classic Cheng/Zhang/Fang set-up):
```
pair_style  hybrid sw morse 6.5
pair_coeff  * * sw Si.sw Si NULL
pair_coeff  1 2 morse 0.435 4.6487 1.9475 6.5
pair_coeff  2 2 none
fix         frz tool setforce 0.0 0.0 0.0
```
(c) Tersoff/MOD Si (Kumagai) + Tersoff C tool + Morse cross term (two many-body sub-styles on *different* objects - manual-sanctioned use):
```
pair_style  hybrid tersoff/mod tersoff morse 6.5
pair_coeff  * * tersoff/mod Si.tersoff.mod Si NULL
pair_coeff  * * tersoff SiC.tersoff NULL C
pair_coeff  1 2 morse 0.435 4.6487 1.9475
```
(d) EDIP Si + rigid tool: replace `sw Si.sw Si NULL` by `edip Si.edip Si NULL` (`pair_style hybrid edip morse 6.5`).

### 4.3 Ge workpiece + diamond tool (bulk Ge from SiCGe.tersoff; Ge.tersoff is a germanene fit)
```
pair_style  hybrid tersoff morse 6.5
pair_coeff  * * tersoff SiCGe.tersoff Ge NULL
pair_coeff  1 2 morse 0.125778 2.58219 2.2324
pair_coeff  2 2 none                                  # rigid tool (Lai et al. 2013)
```
Deformable tool: list `tersoff` twice: `pair_style hybrid tersoff tersoff morse 6.5` ; `pair_coeff * * tersoff 1 SiCGe.tersoff Ge NULL` ; `pair_coeff * * tersoff 2 SiCGe.tersoff NULL C` ; `pair_coeff 1 2 morse ...`. (SiCGe.tersoff has no Ge-C entries, so `Ge C` in one mapping would error.)

### 4.4 Si-Ge alloy / SiGe workpiece + diamond tool
```
pair_style  hybrid tersoff morse 6.5
pair_coeff  * * tersoff SiCGe.tersoff Si(D) Ge NULL   # types 1 Si, 2 Ge, 3 C
pair_coeff  1 3 morse 0.435 4.6487 1.9475
pair_coeff  2 3 morse 0.125778 2.58219 2.2324
pair_coeff  3 3 none
```

### 4.5 Cu workpiece + diamond tool
Rigid tool (types 1 = Cu, 2 = C):
```
pair_style  hybrid eam/alloy morse 6.5
pair_coeff  * * eam/alloy Cu_mishin1.eam.alloy Cu NULL
pair_coeff  1 2 morse 0.087 5.14 2.05 6.5
pair_coeff  2 2 none
fix         frz tool setforce 0.0 0.0 0.0
```
Deformable tool (Tersoff C-C), as in Oluwajobi & Chen / Goel:
```
pair_style  hybrid eam/alloy tersoff morse 6.5
pair_coeff  * * eam/alloy Cu_mishin1.eam.alloy Cu NULL
pair_coeff  * * tersoff SiC.tersoff NULL C            # any file with a C C C entry
pair_coeff  1 2 morse 0.087 5.14 2.05 6.5             # or 0.1063 1.8071 2.3386
```
funcfl variant: `pair_style hybrid eam morse 6.5` ; `pair_coeff 1 1 eam Cu_u3.eam` ; `pair_coeff 1 2 morse ...` ; `pair_coeff 2 2 none`.

### 4.6 Al, Ni, Fe, Au, Ag, W workpieces + diamond tool (template; cross terms per Section 3.1)
```
pair_style  hybrid eam/alloy tersoff morse 6.5        # eam/fs for *_mm.eam.fs ; eam for *_u3.eam (then pair_coeff 1 1 eam file)
pair_coeff  * * eam/alloy <metal file> <El> NULL
pair_coeff  * * tersoff SiC.tersoff NULL C            # drop this line and use "pair_coeff 2 2 none" for a rigid tool
pair_coeff  1 2 morse <D0> <alpha> <r0>
```
File/element per metal: Al -> `eam/fs Al_mm.eam.fs Al` or `eam/alloy Al_zhou.eam.alloy Al`; Ni -> `eam Ni_u3.eam` (type-pair form) or `eam/alloy CuNi.eam.alloy Ni`; Fe -> `eam/fs Fe_mm.eam.fs Fe`; Au -> `eam Au_u3.eam`; Ag -> `eam Ag_u3.eam`; W -> `eam/alloy W_zhou.eam.alloy W`.
Cross term: Ni-C 0.100/2.2/2.4 (partially verified); Al-C, Fe-C, Au-C, Ag-C, W-C **UNVERIFIED** -> use `zbl`:
```
pair_style  hybrid eam/fs zbl 1.0 2.5
pair_coeff  * * eam/fs Fe_mm.eam.fs Fe NULL
pair_coeff  1 2 zbl 26 6
pair_coeff  2 2 none
```

pair_style  hybrid meam/spline morse 6.5
pair_coeff  * * meam/spline Ti.meam.spline Ti NULL    # exactly one type may map to Ti
pair_coeff  1 2 morse 0.982 2.283 1.892               # UNVERIFIED alpha unit (see 3.1)

### 4.8 Diamond workpiece + diamond tool
```

pair_coeff  * * SiC.tersoff C C                       # Tersoff-89 C; or SiC_1994.tersoff (Tersoff-90/94 C)
```
or `pair_style rebo` / `pair_coeff * * CH.rebo C C`, or `pair_style lcbop` / `pair_coeff * * C.lcbop C C`.

### 4.9 GaN workpiece + diamond tool
```
pair_style  hybrid tersoff zbl 1.0 2.5                # Ga-C / N-C Morse not verified -> ZBL wall, rigid tool
pair_coeff  * * tersoff GaN.tersoff Ga N NULL
pair_coeff  1 3 zbl 31 6
pair_coeff  2 3 zbl 7 6
pair_coeff  3 3 none
```
GaAs: `pair_style hybrid bop zbl 1.0 2.5` ; `pair_coeff * * bop GaAs.bop.table Ga As NULL` ; `pair_coeff 1 3 zbl 31 6` ; `pair_coeff 2 3 zbl 33 6` ; `pair_coeff 3 3 none` (BOP needs `mass` set *after* pair_coeff, M 4.16).

### 4.10 Two Tersoff sub-styles on one system (manual's own pattern, M 4.144)
```
pair_style  hybrid lj/cut 2.5 tersoff tersoff
pair_coeff  * * tersoff 1 Si.tersoff Si NULL
pair_coeff  * * tersoff 2 C.tersoff NULL C            # C.tersoff is NOT bundled: use SiC.tersoff NULL C
pair_coeff  1 2 lj/cut 1.0 1.5
```

## 5. Checklist (from the manual) before running
1. `units metal`; `newton on`; `atom_style atomic`.
2. One `* *` line per many-body sub-style; N element tokens = N atom types; `NULL` for types owned by other sub-styles.
3. Every I<=J pair assigned; every sub-style used at least once; **no reliance on mixing** under hybrid.
4. Element tokens must match the file exactly (`Si(D)` in SiCGe.tersoff; `Si C` order for SiC.meam; `Ni Cu` order irrelevant for setfl mapping but must exist in the file).
5. Cutoff for Morse/LJ/ZBL on `pair_style` (6.5 A typical); `morse/smooth/linear` if force continuity at rc matters.
6. Tersoff-family + `fix setforce` on tool; `neigh_modify exclude group tool tool` for a rigid tool.
7. Restart files do **not** store file-based many-body coefficients -> repeat pair_style/pair_coeff after `read_restart` (M 4.299.4).
